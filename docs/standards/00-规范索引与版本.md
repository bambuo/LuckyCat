## 1. 目的

本索引定义 LuckyCat 重构方案与规范集的：

- 文档地图与强制等级；
- 版本号规则与递增条件；
- 状态生命周期；
- 变更时的文档传播矩阵；
- 外部标准与依赖版本的锁定与复核入口。

实现、评审与交付**必须**以本索引列出的文档为准；未列入的文档不具规范效力。

## 2. 规范性用语

按 RFC 2119（见 LC-STD-06 EXT-15）：

- **必须 / 不得**：强制要求，违反即缺陷。
- **应当**：默认要求；偏离需在设计或评审记录中说明理由。
- **可以**：可选。

## 4. 版本规则

### 4.1 文档版本

每份文档独立使用 SemVer 2.0.0（EXT-16）：

| 变更类型 | 版本位 | 示例 |
| --- | --- | --- |
| 破坏规范性内容：角色、工具权限、硬闸顺序、数据删除、公开契约破坏 | MAJOR | 2.0.0 |
| 新增兼容内容：新工具、新字段、新事件、可选项、更严格的默认安全值 | MINOR | 1.1.0 |
| 措辞澄清、示例修正、链接更新、不改变行为的错别字 | PATCH | 1.0.1 |

- 放宽安全限制（提高上限、减少必填校验、扩大工具权限）按 MAJOR 处理。
- 收紧安全限制（降低上限、增加校验）按 MINOR 处理，但必须在变更历史注明影响。
- `LC-SPEC-001` 的 MAJOR 变更**必须**同步更新所有受影响的 LC-STD。
- 版本号出现在文档头部与变更历史；正文不再重复。

### 4.2 递增前提

- 首次落盘为 `1.0.0`。
- **未提交或未交付**的草稿：原地修订，不新增版本行（避免伪造版本历史）。
- 旧版本已提交到仓库或已交付后，才允许新增版本行并递增版本号。
- 已发布的版本行**不得**删除或改写；修正以新版本追加。

### 4.3 提交与发布

- 文档版本由 git 提交承载；规范集发布时提交信息写明版本，例如：
  `docs: 发布 LC-SPEC-001 / LC-STD-00~06 @1.0.0`。
- 每次发布**必须**同时更新：文档头部、变更历史、`版本清单.json`、本索引文档地图。

## 5. 状态生命周期

```text
草案 → 评审 → 定稿（待实施） → 生效 → 废弃
```

| 状态 | 含义 | 允许的实现依据 |
| --- | --- | --- |
| 草案 | 未评审，可能大改 | 否 |
| 评审 | 等待口径确认 | 否 |
| 定稿（待实施） | 方案已确认，代码未落地 | 是（实施依据） |
| 生效 | 代码已实现并通过验收 | 是 |
| 废弃 | 被新版本/新文档替代 | 否（仅追溯） |

- 代码实现完成并通过 LC-STD-05 闸门后，由实现负责人把状态改为「生效」并提升 PATCH（或按变更类型）。
- 废弃文档保留在库中，头部标注替代文档与日期。

## 6. 变更传播矩阵

| 变更内容 | 必须更新 | 应当更新 | 验证 |
| --- | --- | --- | --- |
| 角色/拓扑/条件边 | LC-SPEC-001、LC-STD-01、版本清单 | LC-STD-05 | FLOW-01~05 |
| 工具目录/schema/权限 | LC-STD-02、LC-STD-01（预算）、LC-STD-04（工具规则） | LC-STD-03（错误码）、LC-STD-05 | TOOL-01~12 |
| 硬闸顺序/批准边界 | LC-STD-02、LC-SPEC-001 | LC-STD-05 | EXEC-01~06 |
| 实体/字段/保留策略 | LC-STD-03、版本清单 | LC-SPEC-001 差异清单 | API-01~08 |
| REST/SSE 契约 | LC-STD-03、前端对接文档 | LC-STD-05 | API-01~05 |
| 提示词结构/记忆指纹 | LC-STD-04、LC-SPEC-001 | LC-STD-05 | MEM-01~07 |
| 预算/超时/上限 | LC-STD-01、LC-STD-04（上下文） | LC-STD-05 | FLOW-09 |
| 测试闸门 | LC-STD-05 | — | G1–G8 |
| 依赖/外部标准 | LC-STD-06、版本清单 | LC-SPEC-001 第 11 节 | G1–G3 |
| 复盘流程 | LC-STD-01、LC-STD-04（经验注入） | LC-STD-05 | REVIEW-01~04 |

- 任一变更**必须**在受影响文档的变更历史留一行；不得静默覆盖。
- 实施与文档不一致时，以「代码 + 规范」同时修正为准，不允许只改一边。

## 7. 外部标准与依赖

- 外部规范、NuGet 与前端依赖的完整清单见 LC-STD-06。
- 机器可读版本见 `版本清单.json`；两者不一致时以 JSON 为准，并立即修正 LC-STD-06。
- 复核周期 90 天；当前下次复核日：2027-01-23。
- 升级流程见 LC-STD-06 第 6 节。

## 8. 评审与实施

- 设计评审：LC-SPEC-001 全部章节；口径变更必须记录在决策记录（第 4 节）。
- 实施评审：每个阶段按 LC-STD-05 的闸门验收；未过闸门不得进入下一阶段。
- 代码评审：对照 LC-STD-02（安全）、LC-STD-03（契约）、LC-STD-04（提示词与脱敏）逐项检查。
- 文档评审：检查无 TBD、编号/版本/字段/事件名跨文档一致、示例 JSON 可解析。
