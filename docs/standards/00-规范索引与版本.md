## 1. 目的

本索引定义 LuckyCat 重构方案与规范集的：

- 文档地图与强制等级；
- 版本号规则与递增条件；
- 状态生命周期；
- 变更时的文档传播矩阵；
- 外部标准与依赖版本的锁定与复核入口。

实现、评审与交付**必须**以本索引列出的文档为准；未列入的文档不具规范效力。

## 2. 规范性用语

按 RFC 2119（见 LC-STD-06 EXT-15）：

- **必须 / 不得**：强制要求，违反即缺陷。
- **应当**：默认要求；偏离需在设计或评审记录中说明理由。
- **可以**：可选。

## 4. 版本规则

### 4.1 文档版本

每份文档独立使用 SemVer 2.0.0（EXT-16）：

| 变更类型 | 版本位 | 示例 |
| --- | --- | --- |
| 破坏规范性内容：角色、工具权限、硬闸顺序、数据删除、公开契约破坏 | MAJOR | 2.0.0 |
| 新增兼容内容：新工具、新字段、新事件、可选项、更严格的默认安全值 | MINOR | 1.1.0 |
| 措辞澄清、示例修正、链接更新、不改变行为的错别字 | PATCH | 1.0.1 |

- 放宽安全限制（提高上限、减少必填校验、扩大工具权限）按 MAJOR 处理。
- 收紧安全限制（降低上限、增加校验）按 MINOR 处理，但必须在变更历史注明影响。
- `LC-SPEC-001` 的 MAJOR 变更**必须**同步更新所有受影响的 LC-STD。
- 版本号出现在文档头部与变更历史；正文不再重复。

### 4.2 递增前提

- 首次落盘为 `1.0.0`。
- **未推送且未交付**的草稿：原地修订，不新增版本行（避免伪造版本历史）。
- 旧版本已推送或已交付后，才允许新增版本行并递增版本号。
- 已发布的版本行**不得**删除或改写；修正以新版本追加。

### 4.3 提交与发布

- 文档版本由 git 提交承载；规范集发布时提交信息写明版本，例如：
  `docs: 发布 LC-SPEC-001 / LC-STD-00~06 @1.0.0`。
- 每次发布**必须**同时更新：文档头部、变更历史、`版本清单.json`、本索引文档地图。

## 5. 状态生命周期

```text
草案 → 评审 → 定稿（待实施） → 生效 → 废弃
```

| 状态 | 含义 | 允许的实现依据 |
| --- | --- | --- |
| 草案 | 未评审，可能大改 | 否 |
| 评审 | 等待口径确认 | 否 |
| 定稿（待实施） | 方案已确认，代码未落地 | 是（实施依据） |
| 生效 | 代码已实现并通过验收 | 是 |
| 废弃 | 被新版本/新文档替代 | 否（仅追溯） |

- 代码实现完成并通过 LC-STD-05 闸门后，由实现负责人把状态改为「生效」并提升 PATCH（或按变更类型）。
- 废弃文档保留在库中，头部标注替代文档与日期。

## 11. 语义规则

1. **周期与轮次**：正文统一用“周期”；“本轮 / 每轮 / 轮次”不再使用。
2. **阶段与步骤**：S1–S4 称“阶段”；S5 称“收尾执行器”，不计入阶段；“步骤”仅指写工具硬闸的 1–12 步。
3. **时间**：REST、SSE、模型输出与数据库一律 UTC、RFC 3339、毫秒精度；本地时刻仅用于复盘触发与 UI 展示。
4. **数值**：REST/SSE 中金额、数量、百分比、杠杆为字符串；`positionPct` / `maxPositionPct` 为百分点；`confidence` 为 0–1；权益 = 钱包余额 + 未实现盈亏。
5. **周期状态**：只有 `running` / `completed` / `failed` / `skipped` / `aborted`；不使用 `cancelled`。用户停止记 `aborted`，错误码 `cancelled_by_user`。
6. **SSE 事件名**：`state` / `cycle` / `stage` / `proposal` / `verdict` / `tool` / `order` / `equity` / `position-history` / `ping`；不使用 `plan` / `risk` / `history` 作为事件名。
7. **工具错误码**：使用 `proposal_not_found` / `proposal_not_approved` / `proposal_expired`；不使用 `plan_*`。
8. **边界语义**：行情年龄 ≤3 分钟允许，>3 分钟拒绝；`now ≤ validUntilUtc` 允许，> 拒绝；整 3 分钟与整有效期允许。
9. **风控失败**：fail-closed；周期记 `failed`，不写 `RiskVerdict`，不下单。
10. **文档引用**：同一规范集内可写 `LC-STD-xx §n`（默认当前有效版本）；跨规范集、历史版本或外部引用必须写 `LC-STD-xx@版本` / 外部版本。
11. **历史文档**：README 与旧文档中描述现状的“轮次 / 流水线 / 净值”等历史用语不追溯改写；新写内容必须遵循本节与第 10 节。
12. **平仓路径**：`close` 是降险动作，跳过风控；`open` 必须经风控裁决；平仓仍必须经过写工具硬闸。
