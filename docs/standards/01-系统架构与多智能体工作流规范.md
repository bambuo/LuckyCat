## 1. 目的与范围

本规范定义重构后的运行时结构：角色职责、工作流拓扑、阶段输入/输出、预算与失败语义、并发调度、复盘任务与可观测性。工具与安全见 LC-STD-02，数据与接口见 LC-STD-03，提示词见 LC-STD-04。

规范性用语按 RFC 2119：**必须**、**不得**为强制；**应当**为默认要求，偏离需记录理由；**可以**为可选。

## 2. 架构约束

1. 单进程、单数据库（SQLite）部署；**不得**假设跨进程互斥。
2. 交易决策**必须**经图工作流执行，**不得**在端点或后台服务里直接调用模型生成订单。
3. 模型**不得**直接访问交易所 SDK；只能通过 LC-STD-02 定义的工具。
4. 写操作**必须**经过写工具内的硬闸；风控裁决不能替代硬闸。
5. 每周期工作流**必须**有唯一 `cycleId`，所有阶段、工具、提案、订单都关联该 ID；开仓裁决也关联该 ID。
6. 每周期**必须**落库终态（`completed` / `failed` / `skipped` / `aborted`），即使阶段抛异常。
7. 工作流**不得**跨周期复用 `AgentSession`；会话只服务单阶段的工具循环。
8. 复盘**不得**修改策略、风控配置、交易员状态或历史交易记录。

## 3. 角色

| 角色 | 标识 | 职责 | 禁止 | 模型 |
| --- | --- | --- | --- | --- |
| 分析师 | `analyst` | 扫描候选池，形成结构化研究简报 | 下单、读取账户与持仓（该角色不注入账户数据） | 交易员 Provider |
| 交易员 | `trader` | 结合简报、账户、持仓、记忆与经验，产出提案或观望 | 下单、修改风控配置 | 同上 |
| 风控官 | `risk` | 复核开仓提案，批准（可收紧边界）或拒绝 | 放宽提案、下单 | 同上 |
| 执行员 | `executor` | 在批准边界内提交开仓订单，或直接执行平仓；处理工具错误并报告 | 超出边界、创建新标的、绕过工具 | 同上 |
| 复盘员 | `reviewer` | 复盘已平仓交易与周期，沉淀经验 | 改策略/风控、下单 | 同上 |

角色指令的构建规则见 LC-STD-04。四个交易角色与复盘员**必须**使用交易员绑定的同一 Provider 与模型（LC-SPEC-001 D-03）。

## 4. 工作流拓扑

```text
Start
  │
  ▼
Analyst ──(candidates 为空)──────────────────────────────┐
  │                                                      │
  ▼                                                      │
Trader ──(action = hold)─────────────────────────────────┤
  │                                                      │
  ├──(action = close)──────────────────▶ Executor        │
  │                                                      │
  └──(action = open)──▶ Risk ──(rejected)────────────────┤
                          │                              │
                          └──(approved)──▶ Executor ─────┤
                                                         ▼
                                                     Finalizer
```

### 4.1 图构建

- 使用 `WorkflowBuilder`，起始执行器为 `AnalystExecutor`。
- 条件边使用类型化谓词 `AddEdge<TMessage>(source, target, predicate)`。
- 每个阶段执行器是 `Executor<TIn, TOut>` 子类，负责：
  1. 从 `TradingCycleContext` 取输入与工具；
  2. 调用 `ChatClientAgent.RunAsync<T>` 获取结构化输出；
  3. 校验契约、记录 `AgentStageRun`；
  4. 返回领域记录作为下一条消息。
- 终态信号统一为 `CycleSignal(string Reason)`；收尾执行器（Finalizer）从上下文读取终态并落库、推送 SSE。收尾执行器不调用模型，不产生 `AgentStageRun`，不属于角色枚举。
- 执行器抛异常时工作流失败；`TradingCycleRunner` 的 `finally` **必须**把周期标记为 `failed` 并写入错误摘要。

### 4.2 上下文

`TradingCycleContext` 为单周期作用域对象，至少包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `CycleId` | `string` | ULID 或 GUID；全链路关联键 |
| `TraderId` | `int` | 交易员 |
| `StrategyId` | `int` | 策略 |
| `Provider` | `Provider` | 模型提供商 |
| `Account` | `ExchangeAccount` | 交易所账户 |
| `Config` | `StrategyConfig` | 解析后的策略配置 |
| `Mode` | `dry` / `live` | 执行模式 |
| `Trigger` | `schedule` / `manual` / `test` | 触发来源 |
| `StartedAtUtc` | `DateTimeOffset` | 开始时间 |
| `Market` | `MarketDataCache` | 单周期行情缓存 |
| `Budget` | `CycleBudget` | 工具/token/超时计数 |
| `Recorder` | `CycleRecorder` | 阶段与工具落库 |
| `Outcome` | `CycleOutcome?` | 终态（阶段写入） |

上下文**不得**包含可变静态状态；不同周期之间**不得**共享。

## 5. 阶段契约

### 5.1 研究简报 `ResearchBrief`

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `marketContext` | string | 是 | ≤1,000 字；大盘与情绪摘要 |
| `candidates` | string[] | 是 | 标的（交易对，`BASE/QUOTE` 格式）；按优先级排序；≤10 |
| `symbols` | object[] | 是 | 每项含 `symbol`、`trend`、`keyLevels`、`indicatorSummary`、`risks` |
| `dataWarnings` | string[] | 是 | 数据缺失、陈旧、接口失败；无则 `[]` |

`candidates` 必须来自策略候选池；已持仓标的由交易员处理，分析师不读取账户与持仓。越界标的必须忽略并在 `dataWarnings` 说明。

### 5.2 交易提案 `TradeProposal`

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `action` | `open` / `close` / `hold` | 是 | — |
| `symbol` | string | `open`/`close` 时必填 | 必须在允许集合 |
| `side` | `long` / `short` | `open` 时必填 | — |
| `confidence` | number | 否 | 0–1 |
| `entryPrice` | number | `open` 时必填 | >0 |
| `stopLossPrice` | number | `open` 时必填 | 与方向一致，且 < entry（多）/ > entry（空） |
| `takeProfitPrice` | number | 否 | 与方向一致 |
| `positionPct` | number | `open` 时必填 | (0, 100]；百分点 |
| `leverage` | number | `open` 时必填 | 1–125 |
| `thesis` | string | 是 | ≤1,000 字 |
| `invalidation` | string | `open` 时必填 | 失效条件 |
| `reviewChecklist` | string[] | 否 | 自检项 |

`hold` 时**必须** `action=hold` 且只要求 `thesis`，**不得**携带可执行价格与数量；`close` 时 `symbol` 必填，**不得**携带 `positionPct`、`leverage`、`stopLossPrice`、`takeProfitPrice` 等开仓字段。

### 5.3 风控裁决 `RiskVerdict`

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `decision` | `approved` / `rejected` | 是 | — |
| `reasons` | string[] | 是 | 拒绝时至少 1 条 |
| `maxPositionPct` | number | approved 时必填 | ≤ 提案 `positionPct` |
| `maxLeverage` | number | approved 时必填 | ≤ 提案 `leverage` |
| `entryZoneMin` | number | approved 时必填 | ≤ `entryZoneMax` |
| `entryZoneMax` | number | approved 时必填 | — |
| `allowMarket` | bool | approved 时必填 | 是否允许市价 |
| `validUntilUtc` | string | approved 时必填 | RFC 3339；`validUntilUtc ≤ approvedAt + 10 分钟`；工具在 `now ≤ validUntilUtc` 时允许，超过拒绝 |

风控**不得**给出大于提案的仓位占比或杠杆；违反时服务端按 `rejected` 处理并记录契约错误。**仅 `open` 提案产生裁决**；`close` 是降险动作，跳过风控直接进入执行，不需要 `RiskVerdict`。

### 5.4 执行报告 `ExecutionReport`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `summary` | string | 是 | ≤500 字 |
| `attempts` | object[] | 是 | 每次工具调用的参数摘要、结果、错误码 |
| `orders` | object[] | 是 | `orderId`、`clientOrderId`、状态、成交量、均价 |
| `errors` | string[] | 是 | 无则 `[]` |

报告是叙事层；权威数据以 `TraderOrder` 与 `ToolInvocation` 为准。

## 6. 预算与超时

| 项目 | 默认 | 配置位置 | 超限行为 |
| --- | --- | --- | --- |
| 分析师超时 | 90s | 策略配置 `agentBudget` | 阶段失败 |
| 交易员超时 | 90s | 同上 | 阶段失败 |
| 风控超时 | 45s | 同上 | 阶段失败；按 fail-closed 不下单 |
| 执行超时 | 45s | 同上 | 阶段失败 |
| 单周期总超时 | 300s | 同上 | 取消剩余阶段 |
| 工具/阶段 | 20/14/4/6 | 同上 | 返回 `tool_budget_exceeded` |
| 工具/周期 | 45 | 同上 | 同上 |
| 输入 token/周期 | 见下方公式 | 同上 | 本周期观望 |
| 阶段消息落库 | 128 KiB | 固定 | 截断并标记 |
| 工具结果落库 | 16 KiB | 固定 | 截断并标记 |

超时使用 `CancellationToken` 传播；**不得**用 `Task.WhenAny` 遗留未取消的任务。

输入 token 预算按 `min(150,000, Provider.ContextTokens − effectiveMaxOutputTokens)` 计算，下限 1,000；`effectiveMaxOutputTokens = Provider.MaxOutputTokens > 0 ? Provider.MaxOutputTokens : 16,384`；`Provider.ContextTokens = 0` 时取 150,000。预算在每次模型调用前累计检查，超限不再发起调用。

## 7. 失败语义

| 场景 | 周期状态 | 是否允许下单 | 记忆是否写入 |
| --- | --- | --- | --- |
| 分析失败 | `failed` | 否 | 失败阶段记录；不写提案记忆 |
| 无候选 | `skipped` | 否 | 不写 |
| 交易员 `hold` | `completed` | 否 | 写提案记忆（hold） |
| 交易员契约失败（重试后） | `failed` | 否 | 不写提案 |
| 风控拒绝 | `completed` | 否 | 写提案 + 裁决 |
| 风控失败/超时 | `failed` | 否 | 写失败阶段；不写裁决；fail-closed |
| 写工具拒绝 | `completed`（`errors` 非空） | 否（工具拒绝） | 写提案 + 裁决 + `ToolInvocation` |
| 执行阶段失败（未提交） | `failed` | 否 | 写失败阶段 |
| 执行成功 | `completed` | 是（已执行） | 写提案 + 裁决 + 执行结果 |
| 执行部分失败 | `completed`（`errors` 非空） | 可能已部分成交 | 同上 |
| 进程中断 | `aborted` | — | 保留已落库阶段 |

**fail-closed**：任何无法确认风控裁决的路径都**不得**下单。

## 8. 并发与调度

1. 每个交易员一个调度循环；同一交易员同时最多一个运行中周期。
2. 周期开始前**必须**创建 `TradingCycle` 并提交，状态 `running`。
3. 同一交易所账户的写工具共享进程内 `SemaphoreSlim`；锁**必须**在调用交易所前后覆盖「重读账户 → 校验 → 提交 → 落库」。
4. 只读工具与模型调用**不得**持有账户锁。
5. 调度间隔沿用 3–60 分钟；首个周期立即执行；下个周期从上个周期结束后计间隔。
6. `stop` **必须**取消该交易员当前周期的 `CancellationToken`；取消后**必须**记录 `aborted`，`errorCode=cancelled_by_user`。
7. 启动恢复：读取 `IsRunning` 交易员恢复调度；把所有遗留 `running` 周期标记 `aborted`，`errorCode=process_restart`。
8. 进程内锁**不得**被描述为分布式互斥；多实例部署需外置锁，属于变更范围。

## 9. 复盘任务

| 项目 | 规则 |
| --- | --- |
| 触发 | 本地时刻（默认 00:10）+ 手动端点 |
| 窗口 | 上次成功复盘之后；最多 30 天 |
| 跳过 | 窗口内无已平仓交易且无周期 |
| 输入 | 已平仓交易（经济结果：进出场、净盈亏、手续费）、周期（状态/模式/触发/耗时/token/指纹）、已有经验。提案与裁决**不**在复盘员工具集内：自动注入的记忆块只归交易员（LC-STD-04 §2），复盘证据以标的/周期/订单 ID 引用，不重述提案正文。 |
| 输出 | `TraderLesson`，字段见 LC-STD-03 |
| 限制 | 只读工具；不修改任何配置；单次超时 120s、工具上限 10 |
| 注入 | 最近 3 份，合计 ≤1,200 字 |
| 失败 | 记录失败，不阻塞交易；下个触发点重试 |

复盘**不得**与交易周期并行写同一交易员的记忆；写入使用短事务。

复盘确需提案/裁决正文时，只允许扩 `get_cycles` 的返回载荷，不得私加第四件复盘工具：工具清单变更会提升 `ToolCatalog.Version`，进而改变记忆指纹（LC-STD-04 §5.3）并要求提升修订号。

## 10. 可观测性

每个周期**必须**产生：

- Trace：`trader.cycle` 根 span；每阶段 `agent.stage` 子 span；每次模型调用沿用 M.E.AI 的 `chat` span；每次工具调用 `tool.invoke` span。
- Metrics：周期计数（按状态）、阶段耗时、模型 token、工具调用数/失败数、执行拒绝原因、复盘耗时。
- Logs：周期与阶段 ID、角色、状态、错误码；**不得**记录 API Key、完整请求头、账户密钥。
- SSE：`state`、`cycle`、`stage`、`proposal`、`verdict`、`tool`、`order`、`equity`、`position-history`、`ping`（见 LC-STD-03）。

## 11. 验收判据

1. 六条路由（无候选、hold、开仓被拒、开仓执行、平仓执行、写工具拒绝）都有集成测试。
2. 任一阶段异常时周期终态正确，且不会留下 `running`。
3. 并发测试：同一交易员并发 `start` 只产生一个周期；同账户两交易员写操作串行。
4. 重启恢复测试：遗留 `running` 变为 `aborted`，运行中交易员恢复调度。
5. 复盘跳过、成功、失败三种路径均有测试。
6. 预算超限路径有测试，且超限后不再发起模型或工具调用。
