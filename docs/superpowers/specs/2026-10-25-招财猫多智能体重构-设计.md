## 1. 背景

现状是一套可运行的单周期 AI 决策系统：

- **AI 层极薄**：每周期只有一次无状态 `IChatClient.GetResponseAsync`，system + user 两条消息，没有工具调用、没有会话状态（`Services/StrategyTestRunner.cs:146`）。
- **数据全部预取**：行情、指标、评分榜、消息面、持仓、记忆在调用前拼进提示词，并用 6 级压缩阶梯控制长度（`Services/StrategyTestRunner.cs:197`）。
- **安全在 AI 之外**：决策契约、风控、连亏锁定、行情新鲜度、同账户串行、审计与 SSE 都在代码层（`Services/TradingRiskPolicy.cs:63`、`Services/TraderRunnerService.cs:204`）。
- **工程完整性较好**：56 项测试、OpenTelemetry 埋点、SSE 看板、提供商/交易所验证均可用。

问题不在「能不能跑」，而在架构上限：单次调用无法自主取数、无法分角色复核、无法沉淀结构化经验，提示词一旦膨胀只能粗暴裁剪。Microsoft Agent Framework 1.26.0 提供了 Agent、工具、会话、上下文提供器、中间件与图工作流，正好对应这些缺口。

## 2. 目标与非目标

### 2.1 目标

1. 用 `Microsoft.Agents.AI` + `Microsoft.Agents.AI.Workflows` 重建交易决策链路。
2. 每周期形成 **分析 → 交易 → 风控 → 执行** 的可审计工作流；另设独立的 **复盘** 任务。
3. Agent 通过工具取数与下单；**所有写操作必须经过服务端硬闸**，模型参数不能绕过。
4. 看板能展示每个阶段的输入摘要、工具调用、结构化输出、token 与耗时。
5. 项目未上线，允许重建数据库与 HTTP/SSE 契约；前端同步改造。
6. 一次性替换旧链路，不保留双实现开关。

### 2.2 非目标

- 不重写交易所接入、指标计算、信号评估、账户流与订单网关。
- 不引入多进程/分布式锁；仍是单进程本地服务。
- 不引入人工审批（HITL）交易；交易员保持自主运行。
- 不引入 `Microsoft.Agents.AI.Hosting`（仍为 prerelease）。
- 不做自动改策略参数：复盘只沉淀经验，不改风控与策略。

## 4. 决策记录

| 编号 | 决策 | 理由 | 代价 |
| --- | --- | --- | --- |
| D-01 | 使用 `WorkflowBuilder` 显式图，不用 handoff/group-chat 编排 | 交易路径必须可复现、可审计；图工作流有类型校验与超步边界 | 编排固定，不如自由对话灵活 |
| D-02 | 四段交易角色（分析、交易、风控、执行）+ 收尾；复盘独立 | 职责分离；复盘与交易解耦，避免每周期多付一次模型调用 | 角色与提示词维护量增加 |
| D-03 | 四个交易角色与复盘员共用交易员绑定的 Provider/模型 | 配置与 UI 简单，成本可控 | 无法按角色选更强/更便宜的模型 |
| D-04 | 风控只能维持或收紧提案，不能放宽 | 风控是最后一道语义闸门；收紧可审计 | 模型可能因过度保守降低成交率 |
| D-05 | 执行员可在批准边界内自主调整数量/价格，写工具二次硬闸 | 保留 Agent 的 tool-use 价值，同时杜绝凭空造单 | 同一提案可能产生不同订单，非逐字节可复现 |
| D-06 | 仅保证 UI 可用；HTTP/SSE/DTO 可重设计 | 项目未上线，无外部消费者 | 前端需同步返工 |
| D-07 | 一次性替换，不保留旧执行器开关 | 避免两套决策语义长期并存 | 无灰度回退，只能回滚提交 |
| D-08 | 不引入 Hosting 包，自托管 Minimal API | Hosting 仍是 prerelease；现有 SSE/端点已满足 | 需自己实现会话/事件映射 |
| D-09 | 移除 AI 网格策略类型 | 当前不执行、无独立逻辑，属死功能 | 已有网格策略 JSON 不再导入 |
| D-10 | 不做跨周期对话会话；记忆用上下文提供器注入 | 避免上下文无限增长与成本失控 | 不利用模型的连续对话能力 |
| D-11 | REST/SSE/模型输出统一 camelCase | 消除现有 snake_case 与前端 camelCase 的转换层 | 旧决策字段全部改名 |
| D-12 | 复盘只写经验，不改策略与风控 | 防止模型自行放宽纪律 | 经验需要人工转化为配置 |
| D-13 | 新建交易员默认 `dry`（演练），实盘需显式切换 | Agent 获得下单工具后，默认值必须保守 | 与现有模型默认 `live` 不同，UI 需明确提示 |
| D-14 | 规范文档随代码版本化；外部依赖锁定版本并定期复核 | 重构周期长，避免文档与实现漂移 | 每次契约变更需同步文档版本 |

### 5.2 关键机制

- **工作流按周期构建**：每周期创建作用域上下文（账户、策略、Provider、行情缓存、预算、记录器），图在作用域内构建，避免跨周期状态泄漏。
- **Agent 与执行器分离**：`AnalystExecutor` 等负责调用 `ChatClientAgent.RunAsync<T>`、校验结构化输出、记录阶段；业务决策不写在 Agent 指令之外。
- **工具绑定作用域**：只读工具从缓存取数；写工具额外持有账户锁、批准边界与记录器；模型不能传交易所/账户参数，防止跨账户访问。
- **条件边**：无候选、`hold`、风控拒绝分别路由到收尾；`open` 只有 `approved` 进入执行；`close` 是降险动作，跳过风控直接进入执行。
- **超时与预算**：每阶段独立超时、工具调用上限、每周期 token 预算；超限按失败/观望处理，不静默继续。
- **审计优先**：阶段消息（含工具调用）、工具入参/回执、提案、裁决、执行结果全部落库；SSE 只是展示层。

## 6. 交易周期

### 6.1 阶段与收尾契约

| 阶段/收尾 | 角色 | 输入 | 输出 | 只读工具 | 写工具 | 超时 | 工具上限 |
| --- | --- | --- | --- | --- | --- | ---: | ---: |
| S1 | analyst | 策略候选配置、消息源配置 | `ResearchBrief` | 候选、大盘、K 线、指标、情绪、新闻 | 无 | 90s | 12 |
| S2 | trader | `ResearchBrief`、账户、持仓、记忆、经验 | `TradeProposal`（可 `hold`） | 行情下钻、账户、持仓、最近订单、平仓历史、记忆、经验、纪律 | 无 | 90s | 8 |
| S3 | risk | `TradeProposal`（仅 `open`）、账户、持仓、策略、纪律 | `RiskVerdict` | 账户、持仓、风控配置、纪律 | 无 | 45s | 4 |
| S4 | executor | `open` + `RiskVerdict`，或 `close` | `ExecutionReport` | 账户、持仓、最近订单 | `place_order`、`close_position`、`cancel_order` | 45s | 6 |
| S5 | finalizer | 任一终态 | 无（落库 + SSE） | 无 | 无 | 10s | 0 |

S5 不调用模型，不产生 `AgentStageRun`；阶段角色枚举只有 `analyst` / `trader` / `risk` / `executor` / `reviewer`。

结构化输出记录（字段定义见 LC-STD-01）：

- `ResearchBrief`：`symbols[]`（每个标的的趋势、关键位、指标结论、风险）、`candidates[]`、`marketContext`、`dataWarnings[]`。
- `TradeProposal`：`action`（`open` / `close` / `hold`）、`symbol`、`side`、`confidence`、`entryPrice`、`stopLossPrice`、`takeProfitPrice`、`positionPct`、`leverage`、`thesis`、`invalidation`、`reviewChecklist[]`。
- `RiskVerdict`：`decision`（`approved` / `rejected`）、`reasons[]`、`maxPositionPct`、`maxLeverage`、`entryZoneMin`、`entryZoneMax`、`allowMarket`、`validUntilUtc`。
- `ExecutionReport`：`attempts[]`、`orders[]`、`summary`、`errors[]`。

### 6.2 路由

| 起点 | 条件 | 目标 |
| --- | --- | --- |
| analyst | `candidates` 非空 | trader |
| analyst | `candidates` 为空 | finalizer（状态 `skipped`） |
| trader | `action == hold` | finalizer |
| trader | `action == open` | risk |
| trader | `action == close` | executor（跳过风控） |
| risk | `decision == rejected` | finalizer |
| risk | `decision == approved` | executor |
| executor | 提交完成（成功或失败） | finalizer |

类型谓词用 `WorkflowBuilder.AddEdge<T>(source, target, predicate)`（已核对 1.26.0 API）。收尾执行器接收统一的 `CycleSignal` 信号，从作用域上下文读取终态。

### 6.3 预算

| 项目 | 默认值 | 超限行为 |
| --- | --- | --- |
| 单阶段超时 | S1/S2 90s，S3/S4 45s | 阶段失败；风控失败按 fail-closed 不下单；执行失败记录并结束 |
| 单周期总超时 | 300s | 取消剩余阶段，整个周期失败 |
| 工具调用/阶段 | 见表 6.1 | 工具返回 `tool_budget_exceeded`，后续调用直接拒绝 |
| 工具调用/周期 | 30 | 同上 |
| 输入 token/周期 | `min(150,000, Provider.ContextTokens − effectiveMaxOutputTokens)`，下限 1,000 | 停止后续模型调用，本周期观望 |
| 输出 token/阶段 | 取 Provider 配置（默认 16,384） | 由模型端点限制 |
| 单阶段落库消息 | 128 KiB | 截断并标记 `truncated=true` |
| 工具结果落库 | 16 KiB | 截断并标记 `truncated=true` |

`effectiveMaxOutputTokens` = `Provider.MaxOutputTokens > 0 ? Provider.MaxOutputTokens : 16,384`。

### 6.4 失败语义

| 场景 | 处理 |
| --- | --- |
| 数据工具失败 | 工具返回错误信封；Agent 可换标的/降级；关键数据缺失时提案必须 `hold` |
| 分析阶段失败/空候选 | 周期 `failed` / `skipped`，不下单 |
| 交易员契约解析失败 | 同阶段重试 1 次（带解析错误摘要）；仍失败则周期 `failed` |
| 模型超时 | 阶段失败；重试 1 次；仍失败则周期 `failed` |
| 风控阶段失败/超时 | **fail-closed**：不写裁决、不下单；周期 `failed` |
| 写工具拒绝 | 记录 `ToolInvocation`；仅已提交到交易所的失败/未知才写 `TraderOrder` 失败行；不自动重试同类拒绝；周期 `completed`（`errors` 非空） |
| 执行阶段失败 | 周期 `failed`；记录失败阶段；不自动补单；下个周期根据真实持仓重新决策 |
| 进程中断 | 启动时把 `running` 周期标记为 `aborted`；运行中的交易员恢复调度 |

### 6.5 并发、调度与恢复

- 同一交易员同时最多一个周期；`start` 时若已有周期则返回 409 `cycle_in_progress`。
- 同一交易所账户的**写操作**共享进程内 `SemaphoreSlim`；AI 调用与只读工具不占锁。
- 扫描间隔沿用 3–60 分钟；启动后立即执行首个周期；不重叠。
- 停止交易员取消整个周期 `CancellationToken`；已提交到交易所的订单不可撤回，必须记录并在下个周期纳入持仓。
- 应用重启：运行中的交易员自动恢复；中断周期标记 `aborted`。
- 单进程限制：不提供跨进程互斥；部署多个实例时必须外置锁（非本设计范围）。
- 手动平仓 `POST /traders/{id}/close-position` 创建 `trigger=manual` 的周期（无 AI 阶段），复用 `close_position` 写工具硬闸并审计。

### 6.6 复盘任务

- 触发器：每交易员本地时刻（默认 00:10）+ 手动 `POST /api/traders/{id}/reviews/run`。
- 数据窗口：自上次成功复盘以来；最多 30 天；无已平仓交易且无周期记录则 `skipped`。
- 输出 `TraderLesson`：`summary`、`strengths[]`、`mistakes[]`、`rules[]`（≤10 条，每条 ≤200 字）、`evidence[]`（订单/周期 ID）。
- 注入：交易员上下文注入最近 3 份经验，合计 ≤1,200 字。
- 预算：单次复盘超时 120s、工具调用上限 10；失败只记录，不阻塞交易。
- 权限：复盘员只读；不得修改策略、风控或交易员状态。

## 7. 工具与安全

完整规则见 **LC-STD-02@1.0.0**。核心链路：

```text
交易员提案 positionPct=5%、leverage=10
  → 风控：approved，maxPositionPct=3%、maxLeverage=5、价格带、validUntil
  → 执行员：可提交 2.5%、leverage=4、限价在带内；提交 4% 会被工具拒绝
  → place_order 硬闸：提案存在且已批准 → 未过期 → 参数在边界内 → 最新账户重跑风控
     → 行情新鲜度 ≤3 分钟 → 重复单/周期上限 → 账户锁 → 演练模拟/实盘提交 → 审计
```

- 写工具只允许 `place_order`、`close_position`、`cancel_order`；不提供提币、划转、改杠杆、改 API Key 的工具。
- 模型不能指定 `exchangeAccountId`、`traderId`；工具从作用域绑定。
- 平仓不受「禁止开仓」限制；开仓受风控、纪律、新鲜度、重复单限制。
- 所有写操作使用确定性客户端订单号（含周期、订单键、尝试序号，≤36 字符），数据库唯一索引兜底；规则见 LC-STD-02@1.0.0 §9。
- 演练模式不调用交易所交易与账户接口；按最新价 + 配置手续费/滑点模拟成交，订单标记 `status=filled` + `simulated=true`。
- 工具入参/回执、风控判定、API Key 脱敏后全部落库；写工具与失败调用推送 `tool` SSE 事件。

## 8. 记忆与复盘

- **提案记忆**：最近 8 条 `TradeProposal` 及执行结果；按 `(strategyId, traderId, memoryFingerprint)` 隔离。
- **经验记忆**：最近 3 份 `TraderLesson`。
- **指纹**：`SHA256(promptRevision | 交易员角色指令 | 规范化策略配置 | 工具清单版本)`；任一变化即不注入旧记忆。
- **不持久化跨周期对话**：每个阶段一次 `AgentSession`，生命周期仅限该阶段工具循环；完整消息落 `AgentStageRun` 供审计。
- **上下文提供器**在每次交易员调用前注入记忆与经验，限长、带时间与来源标注；数据与经验都按不可信内容处理。

## 9. 数据与接口

完整定义见 **LC-STD-03@1.0.0**。

### 9.1 数据模型

| 实体 | 用途 | 保留策略 |
| --- | --- | --- |
| `TradingCycle` | 一个周期运行的终态、用量、配置快照与记忆指纹 | 永久 |
| `AgentStageRun` | 阶段指令、消息、输出、token、耗时、错误 | 90 天（消息 >128 KiB 截断） |
| `ToolInvocation` | 工具名、入参、回执、错误码、耗时 | 90 天（结果 >16 KiB 截断） |
| `TradeProposal` | 交易提案（含 hold/close） | 永久 |
| `RiskVerdict` | 风控裁决与批准边界 | 永久 |
| `TraderLesson` | 复盘经验 | 永久 |
| `TraderOrder`（扩展） | 执行审计：`cycleId`、`exchangeAccountId`、`proposalId`、`clientOrderId`、`side`、`status`、`filledQuantity`、`averagePrice`、`simulated`、`leverage` | 永久 |
| 现有 `Provider` / `ExchangeAccount` / `Strategy` / `Trader` / `PositionHistory` / 权益与持仓采样 | 保留 | 沿用 |

`DecisionRecord` 删除；数据库直接删文件重建（`EnsureCreated`），不写迁移。

### 9.2 HTTP 与 SSE

- 所有 REST 响应统一 `{ success, data }` / `{ success: false, error: { code, message } }`。
- 列表统一 `{ items, total, page, pageSize }`；空列表 `[]`，资源不存在 404，业务拒绝 422，状态冲突 409。
- 金额、数量、百分比一律以字符串传输，避免前端浮点精度损失；时间统一 UTC RFC 3339。
- SSE 事件：`state`、`cycle`、`stage`、`proposal`、`verdict`、`tool`、`order`、`equity`、`position-history`、`ping`；不提供断线重放，客户端重连后重新拉取看板。
- 新增端点：周期查询、复盘触发与报告、健康检查；`test-run` 改为流式运行完整工作流的演练模式。

## 10. 前端

- **交易看板**：一个周期一行时间线；阶段卡片按实际路径展示并可展开（输入摘要、工具调用、结构化输出、token/耗时、原始消息）；提案、裁决、订单独立卡片；实时进度来自 `stage` / `tool` 事件。
- **策略工作室**：分析/交易/风控/执行/复盘五页角色指令；`preview-prompts` 展示全部角色提示词与估算 token；工作流试运行以流式展示每段结果；风控、币种来源、指标配置保留。
- **周期历史**：按交易员筛选，展开查看阶段与工具调用。
- **复盘**：报告列表、手动触发、经验注入预览。
- 前端对接文档在实施阶段按 LC-STD-05 的交付要求单独产出（接口、字段、错误文案、示例）。

## 14. 风险与明确接受的代价

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 模型调用从 1 次增至 2–4 次 | token 成本与延迟上升 2–4 倍 | 条件跳过；每阶段工具上限；每周期 token 预算；超限观望 |
| 工具循环不可预测 | 单周期时长波动 | 阶段超时 + 总超时 + 取消传播 |
| 模型不支持 function calling | 分析师/执行员不可用 | 启动交易员前校验 Provider 工具能力；验证面板已覆盖工具调用 |
| 执行员自主调整 | 同一提案结果不同 | 批准边界 + 工具硬闸 + 完整审计链 |
| 结构化输出解析失败 | 阶段失败 | 同阶段一次修复重试；失败即观望 |
| SQLite 写入量上升 | 库体积与锁竞争 | 分表、截断、90 天清理任务（阶段/工具）、写操作短事务 |
| Prompt injection（新闻/外部数据） | 诱导越权或错误决策 | 不可信内容包裹；写工具只认 ID 与边界；风控不读自由文本指令 |
| 本地明文存储 API Key | 设备被入侵即泄露 | 仅监听 localhost、数据库文件权限 600；远程部署前必须加认证与密钥加密 |
| 无灰度开关 | 出问题只能回滚提交 | 一次性替换前完成全部闸门；保留演练模式作为运行期保护 |

## 15. 与现状的差异清单

| 项目 | 现状 | 目标 |
| --- | --- | --- |
| 模型调用 | 每周期 1 次 | 最多 4 次 + 工具往返 |
| 数据获取 | 调用前全量预取 + 6 级压缩 | Agent 通过工具按需取数 |
| 角色 | 单提示词 | 分析 / 交易 / 风控 / 执行 + 复盘 |
| 决策记录 | `DecisionRecord` | `TradingCycle` + `AgentStageRun` + `TradeProposal` + `RiskVerdict` |
| 风控 | 代码校验提案 | 风控官 语义裁决 + 代码硬闸 |
| 下单 | 交易员运行器直接提交 | 执行员 调用写工具（工具内硬闸） |
| 记忆 | 最近 8 条决策注入 | 最近 8 条提案/结果 + 3 份复盘经验 |
| JSON 命名 | snake_case（决策） | camelCase（全链路） |
| 策略 JSON | `strategyType` / `grid` / 单组 Prompt | `roleInstructions` / `agentBudget` / `review` / 分角色 Prompt |
| 网格策略 | 生成提示词但拒绝执行 | 移除 |
| 默认执行模式 | `live` | `dry`（D-13） |
| SSE | `decision` 等旧事件 | `cycle` / `stage` / `proposal` / `verdict` / `tool` 等新事件 |
| 测试 | 56 项 | 保留 25 项风控测试，其余按新契约重写并扩充 |
