# 招财猫桌面版与打包 · 设计

> 日期：2026-10-29　｜　状态：待评审　｜　范围：桌面形态、进程模型、打包与更新

## 1. 目标与非目标

**目标**

- 交付 Windows x64、macOS arm64、Linux x64 三平台桌面安装包，双击即用。
- 桌面版复用现有 Vue 看板与后端管道，界面不重写。
- 关闭主窗口后交易继续运行，托盘可恢复、退出。
- 应用内检查并下载新版本，由用户确认后重启生效。

**非目标**

- 不重写 Avalonia 原生界面；看板、工作室、周期历史仍由现有 Vue 前端提供。
- 不做零端口传输（JS 消息桥）；桌面进程内保留回环 HTTP，见第 2 节。
- 不做自动重启更新；更新是否生效由用户决定。
- 不做旧数据库迁移；桌面版从空库开始，见 5.1。

## 2. 形态与架构

桌面版是**单进程**应用：Avalonia 负责窗口、托盘与生命周期，同一进程内运行现有 ASP.NET Core 管道，通过回环地址提供 API 与前端静态资源，`NativeWebView` 加载本机页面。

```
┌──────────────────── LuckyCat.Desktop.exe ────────────────────┐
│ Velopack hooks → 单实例锁 → Avalonia App                      │
│   无边框窗口：36px 标题栏（品牌 / 导航 / 窗口按钮）             │
│      └─ NativeWebView ──► http://127.0.0.1:<随机端口>/         │
│   托盘：打开 / 数据目录 / 检查更新 / 退出                      │
│   Updater：Velopack + GithubSource                            │
│                                                               │
│   进程内 WebApplication（Kestrel，仅回环）                      │
│     /api/**    现有 Minimal API 端点与 SSE                     │
│     /**        wwwroot 内 web/dist（新增静态托管）              │
│     /internal/activation  显示首实例窗口（桌面模式专用）        │
└───────────────────────────────────────────────────────────────┘
```

- 监听地址固定为 `127.0.0.1`，端口由系统分配（`http://127.0.0.1:0`），启动后从 `IServerAddressesFeature` 读取实际端口。
- 同一份应用仍可由 `dotnet run` 或服务器方式启动：CLI 模式继续监听 `http://localhost:5210`，不启用静态托管，行为与现状一致。
- 前端全部使用相对路径 `/api/**`，同源加载，无需 CORS，SSE 保持浏览器原生实现。

```

    App.axaml(.cs)               生命周期、托盘、ShutdownMode.OnExplicitShutdown
    MainWindow.axaml(.cs)        标题栏 + 启动层 + NativeWebView
    TitleBar.axaml(.cs)          36px 自绘标题栏：品牌、导航、窗口按钮、拖拽与双击最大化
    NavigationBridge.cs          标题栏与网页路由双向同步
    HostBootstrap.cs             数据目录、端口、日志重定向、Build/StartAsync/StopAsync
    SingleInstance.cs            instance.lock / instance.json / 二次启动唤起
    TrayController.cs            托盘菜单与可用性探测
    Updater.cs                   更新检查、下载、重启
    Assets/                      app.ico / app.icns / app.png

scripts/package-desktop.sh       构建、打包、上传（macOS / Linux）
scripts/package-desktop.ps1      Windows 版
```

**主工程改动（仅此三处）**

1. `Program.cs` 抽出 `LuckyCatHost.Build(string[] args, LuckyCatHostOptions options)`；`Program.cs` 保留为 CLI 入口，调用后 `Run()`。
2. `LuckyCatHostOptions` 提供 `ContentRootPath`、`DataDirectory`、`Urls`、`ServeStaticFiles` 四项；SQLite 连接串由固定的 `luckycat.db` 改为 `Path.Combine(DataDirectory, "luckycat.db")`。
3. `wwwroot` 存在时注册静态托管与 SPA 回退（第 6 节）；不存在时保持现状。

业务代码、端点与契约不改动。

`LuckyCatHostOptions.Development()` 复现当前行为：内容根为工作目录、数据目录为工作目录、`Urls = "http://localhost:5210"`、不托管静态文件。

**前端桌面适配（壳层，不改业务页面）**

| 文件 | 改动 |
| --- | --- |
| `web/src/App.vue` | 桌面模式标记存在时隐藏整个 header |
| `web/src/main.ts` | 首次加载时把 `?desktop=1` 写入 `sessionStorage`（路由跳转会丢弃查询参数）；暴露 `window.__lcNavigate = (path) => router.push(path)` |
| `web/src/router.ts` | `afterEach` 通过 `invokeCSharpAction` 回传当前路由 |
| `web/src/style.css` | 新增 `--app-header-height`，默认 `56px`；桌面模式设为 `0px` |
| `web/src/pages/StrategyStudioPage.vue` | 高度由 `calc(100vh - 56px)` 改为 `calc(100vh - var(--app-header-height, 56px))` |

## 4. 启动、关闭与单实例

**启动序列**

1. `VelopackApp.Build().Run()` —— 最先执行，处理安装与更新钩子。
2. 取得单实例文件锁；已有实例时，读取 `instance.json` 的地址，`POST /internal/activation` 唤起对方窗口，本进程退出。
3. 创建 Avalonia 应用与托盘，显示主窗口的启动层（进度与状态文字）。
4. 后台执行：重定向控制台输出到日志 → 构建并 `StartAsync` 应用管道 → 读取实际端口 → 写入 `instance.json` → 导航 `NativeWebView`。
5. 导航完成（`NavigationCompleted.IsSuccess`）后隐藏启动层；失败时启动层显示错误、日志路径、「重试」与「打开日志」。
6. 启动 60 秒后开始更新检查，此后每 6 小时一次。

**关闭与退出**

- 关闭主窗口：托盘可用时隐藏窗口，交易继续；托盘不可用时直接退出。
- 托盘「退出」：停止应用管道（`StopAsync`）→ 释放锁 → 结束进程。
- 应用退出不额外停止交易员；重启后由 `CycleStartupRecovery` 收敛遗留 `running` 周期为 `aborted`，并按 `IsRunning` 恢复调度。桌面版不改变该语义。
- `ShutdownMode = OnExplicitShutdown`，窗口关闭不退出进程。

**首次关窗提示**：首次隐藏到托盘时显示一次提示（「已最小化到托盘，交易继续运行」），记录于数据目录 `desktop.json` 的 `closeToTrayHintShown`。

## 5. 运行期配置

### 5.1 数据目录

| 平台 | 默认目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\LuckyCat` |
| macOS | `~/Library/Application Support/LuckyCat` |
| Linux | `~/.local/share/LuckyCat` |

实现取 `Environment.GetFolderPath(SpecialFolder.LocalApplicationData)` 拼接 `LuckyCat`；环境变量 `LUCKYCAT_DATA_DIR` 可覆盖。

```
<data>/
  luckycat.db, luckycat.db-wal, luckycat.db-shm
  logs/app-YYYYMMDD.log
  instance.json       { "url": "http://127.0.0.1:53412", "pid": 12345 }
  desktop.json        { "closeToTrayHintShown": true }
```

桌面版不读取、不复制仓库根或其他目录的既有 `luckycat.db`；首次启动在数据目录 `EnsureCreated` 建空库。开发与服务器形态仍使用工作目录下的数据库。

### 5.2 端口与访问

- 桌面模式：`http://127.0.0.1:0`，系统分配端口；实际地址写入 `instance.json`，托盘菜单提供「复制服务地址」便于调试。
- CLI 模式：`http://localhost:5210`，与运维手册一致。
- 不新增鉴权；访问边界仍为本机单用户。回环绑定与随机端口只降低暴露面，不构成安全边界。

### 5.3 日志

GUI 进程无控制台，桌面模式在构建管道前执行 `Console.SetOut` / `Console.SetError` 重定向到 `<data>/logs/app-YYYYMMDD.log`（追加、UTF-8），现有 `Console.WriteLine` 与默认 Console 日志提供器一并落盘。启动时清理 7 天前的日志文件。不引入第三方日志库。

### 5.4 单实例

- 锁文件 `<data>/instance.lock`，以 `FileShare.None` 持有至退出。
- 二次启动读取 `instance.json`，向 `/internal/activation` 发一次 POST：成功则退出本进程；失败（实例文件缺失或地址不可达）则显示「已有实例在运行但无法唤起」并退出，不启动第二份后端。
- `/internal/activation` 仅桌面模式注册，仅接受回环来源，不接受外部输入，行为是把首实例窗口显示并置前。

## 6. 静态托管与路由

- 桌面发布产物包含 `wwwroot`（来自 `web/dist`）。`wwwroot` 存在时注册 `UseDefaultFiles` 与 `UseStaticFiles`。
- SPA 回退规则：非 `/api` 的未匹配 GET 返回 `index.html`；`/api/**` 未匹配返回现有格式的 JSON 404，不返回 HTML。
- 前端使用 `createWebHistory`，由上述回退支持深链；不改为 hash 路由。
- 桌面入口地址为 `http://127.0.0.1:<port>/traders?desktop=1`；前端首次加载时把该标记写入 `sessionStorage`，后续路由跳转与刷新都以该标记判定桌面模式。
- 不启用 CORS、不注册自定义协议。

## 7. 窗口与桌面交互

### 7.1 无边框窗口

- 窗口启用 `ExtendClientAreaToDecorationsHint` 并隐藏系统标题栏，三平台统一自绘；不使用透明窗口与自绘圆角，圆角、阴影与贴边分屏交给系统。
- 布局：顶部 36px 标题栏 + 下方 `NativeWebView` 填满剩余区域；启动层覆盖在 WebView 区域上，不覆盖标题栏。
- 标题栏底色 `#fff`，底边 1px `#e5e6eb`，与页面同色连成一体。
- 品牌区：logo 20px + 「招财猫」13px/600，左内边距 12px；品牌区与导航之间 1px `#e5e6eb` 竖线。
- 导航：AI 交易员 / 策略工作室 / 周期历史 / 复盘经验，13px，项高 28px，圆角 6px，间距 2px；选中态 `#FFF4D6` 底 + `#8A5A00` 字；悬停态 `#f2f3f5`。
- 窗口按钮：右上角三枚 36×36；悬停 `#f2f3f5`，关闭悬停 `#e81123` 白图标；最大化时中间按钮切换为还原。
- 品牌区与空白区域拖拽移动，双击切换最大化；导航项与窗口按钮不参与拖拽。
- 窗口最小尺寸 1080×720，导航不做窄屏折叠。

### 7.2 导航同步

- 桌面到网页：点击标题栏导航调用 `InvokeScript("window.__lcNavigate('<path>')")`，前端经 `router.push` 切换，不重载页面，SSE 连接保持。
- 网页到桌面：`router.afterEach` 通过 `invokeCSharpAction({type:'route', path})` 回传，标题栏据此更新选中态；页面内部跳转同样生效。
- 消息桥只同步路由，API 与 SSE 仍走回环 HTTP。

### 7.3 托盘、外链与提示层

- 托盘菜单：打开主窗口 / 复制服务地址 / 打开数据目录 / 检查更新 / 退出。
- 外链处理：`NewWindowRequested` 与导航到非本机回环地址一律交给系统浏览器；应用窗口只加载本机地址。
- **提示类界面不得叠加在 WebView 上**：`NativeWebView` 是原生层，覆盖其上的 Avalonia 控件不可见。更新提示、错误详情、首次关窗提示均使用独立 `Window`。
- Linux 托盘探测：检查当前会话 D-Bus 上是否存在 `org.kde.StatusNotifierWatcher`；不存在即视为托盘不可用，关闭窗口直接退出，并在启动层日志中记录该判定。

### 7.4 平台差异

- macOS 无系统红绿灯，补充系统菜单栏（关于招财猫 / 隐藏 / 退出）与 ⌘Q、⌘W 快捷键；⌘W 隐藏窗口而非退出进程。
- Linux Wayland 下自绘标题栏的拖拽可能受限，作为已知限制记录。
- 三平台窗口按钮统一置于右上角；macOS 的位置不符合其平台惯例，属于统一视觉的取舍。

## 8. 自动更新

- 更新源：`new GithubSource("https://github.com/bambuo/LuckyCat", accessToken: null, prerelease: false)`。仓库公开，匿名访问受每小时 60 次/IP 限制；检查频率为启动后一次、此后每 6 小时一次。
- 流程：检查 → 后台下载 → 提示「新版本 vX 已下载」→ 用户选择「立即重启」或「稍后」。
- 不自动重启。提示文案在存在运行中交易员时明确写出：重启会中断当前周期，重启后运行中的交易员自动恢复调度。
- 检查失败、下载失败只在日志与托盘提示中记录，不打断交易。
- 手动入口：托盘「检查更新」立即执行一次检查。

## 9. 打包与发布

**版本**：`Directory.Build.props` 的 `<Version>` 为唯一来源，打包脚本从中读取传给 `vpk`。

**流水线**（三平台分别执行）

```
cd web && bun install && bun run build
dotnet publish desktop/LuckyCat.Desktop -c Release -r <rid> --self-contained -p:PublishSingleFile=false
vpk pack -u LuckyCat -v <version> -p <publishDir> --mainExe <LuckyCat.Desktop.exe | LuckyCat.Desktop> --packTitle 招财猫 --icon <icon>
vpk upload github --repoUrl https://github.com/bambuo/LuckyCat --token $GH_TOKEN --publish
```

| 平台 | rid | 附加参数 | 产物 |
| --- | --- | --- | --- |
| Windows x64 | `win-x64` | `--framework webview2`、`--icon Assets/app.ico` | `Setup.exe` |
| macOS arm64 | `osx-arm64` | `--icon Assets/app.icns` | `.pkg`，附带可移植 `.zip` |
| Linux x64 | `linux-x64` | `--icon Assets/app.png --categories Finance` | `.AppImage` |

- Windows 安装器声明 WebView2 运行时依赖；自包含发布只声明 `webview2`，不声明 .NET。
- 图标由 `web/public/logo.svg` 生成三套位图资产，作为实现任务的一部分。
- 首版由本地脚本发布；GitHub Actions 三平台矩阵作为后续可选项，不阻塞首版。

## 10. 测试与验收

**自动化**

- 现有后端与前端测试全部通过；`LuckyCatHost.Build` 抽离属零行为变更。
- 新增单元测试：`LuckyCatHostOptions` 解析、静态托管与 SPA 回退、`/api/**` 未命中返回 JSON 404、数据目录与日志路径解析、单实例锁行为、更新检查与下载的纯函数逻辑（重启只能由用户确认触发）、桌面模式标记判定、标题栏菜单项与路由的映射关系。
- 桌面 UI 不进入自动化测试；`TrayController` 的托盘可用性判定以纯函数暴露并单测。

**打包验收（三平台手工）**

1. 干净环境安装 → 启动 → 看板加载、SSE 秒推。
2. 标题栏导航切换：页面不重载、SSE 不断、选中态正确；页面内部跳转时标题栏同步。
3. 拖拽标题栏移动窗口、双击最大化、最大化后按钮状态正确；关闭窗口后托盘恢复。
4. 交易员周期在窗口隐藏期间继续推进。
5. 二次启动 → 唤起首实例窗口，不产生第二份后端。
6. 退出 → 进程结束、锁释放；再次启动正常。
7. 发布新版本 → 应用内检测到 → 下载 → 确认重启 → 版本更新且数据目录保留。
8. Linux 无托盘环境：关闭窗口直接退出，日志记录判定原因。

## 11. 风险与限制

| 项 | 影响 | 处置 |
| --- | --- | --- |
| macOS 签名与公证 | 未签名 `.pkg` 首次启动被 Gatekeeper 拦截 | 需要 Apple Developer 证书（年费）；无证书时交付未签名包并在发布说明给出右键打开步骤 |
| Windows 代码签名 | 未签名安装器触发 SmartScreen | 可选 Azure Artifact Signing；首版接受警告 |
| Linux 运行依赖 | AppImage 不打包系统库；需 WebKitGTK 4.1、GTK3、FUSE 2 | 发布说明给出 apt 依赖；启动失败时启动层展示安装提示 |
| Linux 托盘 | GNOME 默认无托盘扩展 | 无 StatusNotifier 时关闭即退出 |
| WebView2 运行时 | 旧版 Windows 可能缺失 | 安装器 `--framework webview2` 自动补装 |
| 原生层遮挡 | Avalonia 弹层在 WebView 上不可见 | 提示类界面一律独立窗口 |
| GitHub 匿名限流 | 60 次/小时/IP | 检查频率每 6 小时；失败静默重试 |
| 更新重启 | 中断进行中周期 | 用户确认后重启；`CycleStartupRecovery` 保证恢复 |
| 导航双份维护 | 标题栏与网页 header 是两套 UI | 桌面隐藏 header，网页版保留；新增菜单项需同时修改两处 |
| macOS 窗口惯例 | 无红绿灯、按钮在右上，与平台习惯不符 | 提供系统菜单栏与 ⌘Q/⌘W；发布说明写明 |
| Linux Wayland 拖拽 | 无边框窗口可能无法拖动 | 记录为已知限制；必要时以环境变量回退系统标题栏 |
| 36px 信息密度 | 品牌 + 四项导航 + 三按钮在窄窗口拥挤 | 最小窗口 1080×720，不折叠导航 |
| 随机端口 | 调试无法固定地址 | 托盘「复制服务地址」；`instance.json` 可查 |
| Velopack 限制 | macOS App Sandbox 不受支持 | 不做沙盒分发 |
