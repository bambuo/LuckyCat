## 二、运行形态

- **后端**：单进程 ASP.NET Core，固定监听 `http://localhost:5210`（`Program.cs:16`）；数据库为进程当前目录下的 `luckycat.db`（SQLite）。
- **前端开发**：`bun run dev` 起 Vite（默认 5173），`/api` 代理到 5210（`web/vite.config.ts`）。
- **前端生产**：`bun run build` 产出 `web/dist/`，由任意静态服务器托管，并把 `/api` 反向代理到 5210（前端以同源 `/api` 调用，无跨域配置）。
- **面向范围**：仅本机使用，**无鉴权**；不要直接暴露到公网（详见运维手册「安全约束」）。

## 三、部署步骤

### 3.1 全新空库

```bash
dotnet run --project LuckyCat.csproj --no-launch-profile   # 首次启动由 EnsureCreated 按当前模型建表
cd web && bun install && bun run build                      # 产出 dist
```

### 3.2 已有数据库（升级）

```bash
# 1) 停服务并备份
cp luckycat.db luckycat.db.bak-$(date +%Y%m%d%H%M%S)
# 2) 执行迁移（新建 6 张表、给 Providers/TraderOrders 补列）
sqlite3 luckycat.db < docs/sql/2026-10-26-多智能体新表.sql
# 3) 启动并验证
curl -s http://localhost:5210/api/health
```

注意：脚本第 2 节是一次性 `ALTER TABLE`，重复执行会报「列已存在 / 无此列」；第 1、3 节可重复执行。旧决策表 `DecisionRecords` 不再读写，脚本默认不删数据。

### 3.3 首次使用顺序

1. 「添加模型」→ 填 BaseUrl/模型/API Key → 点「验证」；验证通过后才会写入工具调用能力（未验证的模型无法启动交易员或试运行，返回 422）。
2. 「添加交易所」→ 填 Gate/Binance 等凭据（Gate 无需 IP 白名单）。
3. 「创建交易员」→ 绑定模型、交易所、策略 → 「启动」。

## 四、配置与密钥

- 模型与交易所凭据保存在数据库（`Providers.ApiKey` / `ExchangeAccounts.ApiKey`），读取接口只返回掩码；不要把它们提交进版本库。
- 唯一的运行期环境变量与可观测性有关：`OTEL_EXPORTER_OTLP_ENDPOINT`（启用 OTLP 导出）、`OTEL_CONSOLE=1`（控制台导出，本地调试用）。不设置时零噪声。
- 工具预算、阶段超时、复盘时刻等属于策略配置（`StrategyConfig.agentBudget` / `review`），在策略工作室修改；**已保存的策略会钉住当时的预算值**，改默认常量不会追溯。

## 五、验收边界与运行预期

1. **无鉴权、仅本机**：应用只监听 `localhost`；远程访问需先加认证与 TLS。
2. **前端自动化范围**：`bun test` 覆盖 SSE 帧解析等纯函数；页面交互与实时刷新以人工浏览器验收为准。
3. **外部消息源无 SLA**：单个源失败只记 warning（`源 X 缺席：…`），不影响交易周期；端点变更按 `docs/standards/06-外部标准与版本.md` 维护。
4. **试运行不下单**：`trigger=test` 使用合成账户，执行阶段的交易/账户请求按规范被拒绝，这是设计行为。
5. **金额线上格式**：REST/SSE 金额、数量、百分比、杠杆均为字符串（服务端 `decimal` 解析）；前端算术前显式 `Number()` 并加守卫。

## 六、回滚

- 代码：`git revert` 本分支的提交；或切回 `main`。
- 数据库：升级只做加法（新表 + 补列），回滚代码不会破坏旧表的读写；如需彻底回到旧版本，用 3.2 的备份文件覆盖。`TraderOrders.Success` 已被删除，旧版本代码若依赖该列需一并恢复备份。
