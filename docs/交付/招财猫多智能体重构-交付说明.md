## 二、运行形态

- **后端**：单进程 ASP.NET Core，固定监听 `http://localhost:5210`（`Program.cs:16`）；数据库为进程当前目录下的 `luckycat.db`（SQLite）。
- **前端开发**：`bun run dev` 起 Vite（默认 5173），`/api` 代理到 5210（`web/vite.config.ts`）。
- **前端生产**：`bun run build` 产出 `web/dist/`，由任意静态服务器托管，并把 `/api` 反向代理到 5210（前端以同源 `/api` 调用，无跨域配置）。
- **真实依赖**：模型与交易所使用你在「添加模型 / 添加交易所」中配置的真实凭据，运行时发起真实请求；`dry` 只表示不向交易所提交订单。
- **面向范围**：仅本机使用，**无鉴权**；不要直接暴露到公网（详见运维手册「安全约束」）。

## 三、部署步骤

### 3.1 全新空库

```bash
dotnet run --project LuckyCat.csproj --no-launch-profile   # 首次启动由 EnsureCreated 按当前模型建表
cd web && bun install && bun run build                      # 产出 dist
```

### 3.2 已有数据库（升级）

```bash
# 1) 停服务并备份
cp luckycat.db luckycat.db.bak-$(date +%Y%m%d%H%M%S)
# 2) 执行迁移（新建 6 张表、给 Providers/TraderOrders 补列）
sqlite3 luckycat.db < docs/sql/2026-10-26-多智能体新表.sql
# 3) 启动并验证
curl -s http://localhost:5210/api/health
```

注意：脚本第 2 节是一次性 `ALTER TABLE`，重复执行会报「列已存在 / 无此列」；第 1、3 节可重复执行。旧决策表 `DecisionRecords` 不再读写，脚本默认不删数据。

### 3.3 首次使用顺序

1. 「添加模型」→ 填 BaseUrl/模型/API Key → 点「验证」；验证通过后才会写入工具调用能力（未验证的模型无法启动交易员或试运行，返回 422）。
2. 「添加交易所」→ 填 Gate/Binance 等凭据（Gate 无需 IP 白名单）。
3. 「创建交易员」→ 绑定模型、交易所、策略 → 「启动」。

## 四、配置与密钥

- 模型与交易所凭据保存在数据库（`Providers.ApiKey` / `ExchangeAccounts.ApiKey`），读取接口只返回掩码；不要把它们提交进版本库。
- 服务器 / CLI 形态的运行期环境变量只与可观测性有关：`OTEL_EXPORTER_OTLP_ENDPOINT`（启用 OTLP 导出）、`OTEL_CONSOLE=1`（控制台导出，本地调试用）。不设置时零噪声。桌面形态另有 `LUCKYCAT_DATA_DIR` 与测试钩子 `LUCKYCAT_DISABLE_TRAY`，见运维手册「桌面模式」。
- 工具预算、阶段超时、复盘时刻等属于策略配置（`StrategyConfig.agentBudget` / `review`），在策略工作室修改；**已保存的策略会钉住当时的预算值**，改默认常量不会追溯。

## 五、验收边界与运行预期

1. **无鉴权、仅本机**：应用只监听 `localhost`；远程访问需先加认证与 TLS。
2. **前端自动化范围**：`bun test` 覆盖 SSE 帧解析等纯函数；页面交互与实时刷新以人工浏览器验收为准。
3. **内置新闻源依赖第三方站点**：单个源失败只记 warning（`源 X 缺席：…`），不影响交易周期；端点变更按 `docs/standards/06-外部标准与版本.md` 维护。
4. **试运行不下单**：`trigger=test` 使用合成账户，执行阶段的交易/账户请求按规范被拒绝，这是设计行为。
5. **金额线上格式**：REST/SSE 金额、数量、百分比、杠杆均为字符串（服务端 `decimal` 解析）；前端算术前显式 `Number()` 并加守卫。

## 六、桌面版

> 分支：`main`（0.1.1 已发布）｜版本：0.1.1

桌面版是单进程应用：Avalonia 负责窗口、托盘与生命周期，同一进程内运行现有 ASP.NET Core 管道，只监听 `127.0.0.1` 的随机端口，`NativeWebView` 加载本机页面。CLI 形态、数据目录与仓库根 `luckycat.db` 均不受影响。

### 6.1 产物清单

本机（macOS arm64）实测产物在 `artifacts/releases/`（`artifacts/` 不入库）：

| 文件 | 用途 |
| --- | --- |
| `bambuo.LuckyCat-0.1.1-osx-Setup.pkg` | macOS 安装包 |
| `bambuo.LuckyCat-0.1.1-osx-Portable.zip` | macOS 免安装包，解压得到 `招财猫.app` |
| `bambuo.LuckyCat-0.1.1-osx-full.nupkg` | 自动更新用的完整包 |
| `RELEASES-osx` | 更新通道清单 |
| `assets.osx.json`、`releases.osx.json` | 发布与资产元数据 |

产物统一命名为 `bambuo.LuckyCat-<version>-<channel>...`；vpk 原始产物不带版本号，打包脚本在 `vpk pack` 后用 `scripts/rename-artifacts.sh` 改名并同步 feed。包结构已核对：`招财猫.app/Contents/MacOS/LuckyCat.Desktop` 与 `Contents/MacOS/wwwroot/index.html` 均存在，`CFBundleIdentifier=com.bambuo.luckycat`。

Windows（`win-x64`）由 `scripts/package-desktop.ps1` 生成（`bambuo.LuckyCat-0.1.1-win-*`）；本机未执行，文件名未实测。Linux 的 `linux-x64` 与 `linux-arm64` 在 Linux 容器内用 `scripts/package-desktop.sh` 打包，实测产物为 `bambuo.LuckyCat-0.1.1-linux.AppImage`（x64，95.0 MB）与 `bambuo.LuckyCat-0.1.1-linux-arm64.AppImage`（arm64，91.8 MB），各自带 `-full.nupkg` 与 `releases.linux*.json`；两架构分属 `linux` 与 `linux-arm64` 两个更新 channel。0.1.1 已上传 GitHub Releases，共 10 个资产。

Velopack 的 `-u`（packId）为 `bambuo.LuckyCat`：Windows 安装根为 `%LOCALAPPDATA%\bambuo.LuckyCat`，数据目录仍是 `%LOCALAPPDATA%\LuckyCat`，两者分离，卸载不会删除交易库；macOS 的应用安装位置不受 packId 影响。

### 6.2 签名状态

- **macOS**：`.pkg` 与 `招财猫.app` 均未签名、未公证。首次启动会被 Gatekeeper 拦截，需在「系统设置 → 隐私与安全性」放行，或执行 `xattr -dr com.apple.quarantine /Applications/招财猫.app`。
- **Windows**：安装器与程序未做代码签名，SmartScreen 会提示「未知发布者」，需用户确认后继续。
- **Bundle ID**：`CFBundleIdentifier=com.bambuo.luckycat`，由 `--bundleId` 显式指定；首版尚未上传，后续版本沿用该值，不能再改，否则会断开更新链。

### 6.3 与 spec 的偏差

与 spec 的偏差：Windows 安装器不声明 WebView2 依赖；Linux 包必须在 Linux 主机或容器内构建。

- **Windows**：安装器不随包安装 WebView2 运行时；目标机缺少 WebView2 Runtime 时桌面版无法启动，需安装后补装。
- **Linux**：macOS 的 vpk 不能交叉打 Linux 包；本次在 `mcr.microsoft.com/dotnet/sdk:10.0` 容器中配合 `squashfs-tools` 产出 AppImage。Linux 主机下 `--categories Finance` 可用，`.desktop` 已带 `Categories=Finance;`，无分类偏差。
- **启动层**：宿主就绪即关闭启动窗，不等待页面导航完成；首次页面加载失败用独立提示窗报告，但没有「重试」按钮，重试需重启应用。
- **packId**：Velopack 的 packId 由 `LuckyCat` 改为 `bambuo.LuckyCat`，使 Windows 安装根 `%LOCALAPPDATA%\bambuo.LuckyCat` 与数据目录 `%LOCALAPPDATA%\LuckyCat` 分离，避免卸载删除交易库。产物名与 Bundle ID 随之变化；首版未发布，若本机装过旧的 `LuckyCat` 本地包，需先卸载再装新包，更新链从本版重新开始。

原因是 vpk 的 `--framework webview2` 在 1.2.161 与 1.3.39-g8d2844f 均不提供；Windows 打包缺此能力时脚本硬失败，显式设置 `LUCKYCAT_ALLOW_MISSING_WEBVIEW2=1` 才能继续，生产发布不应设置该放行变量。

- 网页外链转交系统浏览器（`target="_blank"` 与站外导航）。
- 看板内的 SSE 展示。
- 更新检查、下载与「立即重启」后的版本切换，含「稍后」后的托盘强制重弹提示。

已实测：后端 480 项测试连续 3 次全绿、前端 12 项测试、打包脚本 bash 语法、macOS 包结构与 `wwwroot/index.html` 存在、本版产物名为 `bambuo.LuckyCat-*` 且 `CFBundleIdentifier=com.bambuo.luckycat`、宿主探针（`/api/health`、`/internal/activation`、日志、`instance.json`）、第二实例进程判定（headless 探针；窗口唤起未实测）、坏 `instance.json` 拒绝激活、只读数据目录返回 `UnauthorizedAccessException`；Linux x64/arm64 AppImage 在容器内打包成功并通过内容校验（ELF 架构、`usr/bin/LuckyCat.Desktop`、`wwwroot`、`.desktop` 的 `Name=招财猫` 与 `Categories=Finance;`）；GitHub Release 0.1.1 已发布，共 10 个资产（macOS 4、Linux x64 3、arm64 3）。启动包装可执行文件同样终止于 `RenderTimer -6661`，该未处理异常按预期写入 `<数据目录>/logs/app-YYYYMMDD.log`。

### 6.5 已知限制

- **Linux Wayland**：无边框窗口由自绘标题栏拖动，Wayland 下拖拽可能受限。
- **无托盘**：Linux 会话没有 StatusNotifier 宿主（GNOME 默认无托盘扩展）时，关闭窗口即退出进程，交易不能继续。
- **Linux 自动更新**：x64 与 arm64 分属 `linux` / `linux-arm64` channel，Velopack 按安装包内记录的 channel 拉取更新，两架构不会互相拉到对方包。
- **Velopack 版本偏斜**：程序引用 Velopack SDK 1.2.161，打包使用 CLI 1.3.39-g8d2844f；本机打包与清单生成正常，但两个版本未对齐，升级时应同步。
- 回环绑定与随机端口只降低暴露面，不构成安全边界；桌面版仍无鉴权，只适用于单用户本机。
